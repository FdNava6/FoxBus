# Flujo de contribución

El equipo trabajará mediante ramas individuales o ramas por funcionalidad. No se recomienda desarrollar directamente sobre `main`.

## Pasos

1. Actualizar `main` desde el repositorio remoto.
2. Crear una rama descriptiva, por ejemplo `usuario/funcionalidad`.
3. Realizar cambios pequeños y verificables.
4. Ejecutar `npm run lint`, `npm test` y `npm run build` dentro de `frontend`.
5. Subir la rama y abrir un pull request.
6. Solicitar revisión antes de fusionar.

## Convención de commits

- `feat:` nueva función.
- `fix:` corrección de comportamiento.
- `docs:` documentación.
- `chore:` mantenimiento sin cambio funcional.

Cada integrante debe usar en Git el correo asociado a su cuenta de GitHub para que sus aportes sean atribuidos correctamente.
